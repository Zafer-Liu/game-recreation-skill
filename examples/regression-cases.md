# 质量流程回归场景

这些是后续评估 Skill 的场景与判据，**尚未执行，不是成功案例或质量基准分数**。运行生成、依赖安装、构建或浏览器操作仍需对应授权。评估记录参考、任务约束、源码/产物版本、普通输入路线、画面对照与失败原因；不以 agent 自评分代替产物。

| 场景与输入 | 应得到的决策/证据 | 失败信号 |
| --- | --- | --- |
| 只有大型 3D 游戏名 | 补可访问的参考或明示缺口，选代表场景与辨识度目标 | 凭记忆扩成全功能工程，未看画面就宣称还原 |
| 2D 棋盘/消除游戏截图 | 棋盘布局、格子比例、字体/色块对照；未知规则写设计选择；实际点击区域准确 | 默认引入 3D/物理，画面缩放后点错格 |
| 2D 平台游戏录屏 | 一个角色、一个代表障碍、移动/跳跃/接触节奏与取景，能失败并重来 | 很多关卡但跳跃手感或角色比例始终是占位 |
| 3D 探索/动作切片 | 主体轮廓、相机朝向与前进一致；目标在可见可达范围；有空间尺度参照 | 只有漂亮天空与随机原语，按前进却朝镜头走 |
| 物理建造或资源规划 | 核算材料数量、获取/搬运顺序、容量/成本、移动能力与目标路线；固定子步与渲染频率契约一致 | 配方缺材料，表示能拼但普通输入凑不到，能力无法跨过实际距离 |
| 小体积约束与关键美术冲突 | 给关键对象选择合理表示，删背景广度保识别点；解释硬约束冲突 | 未经用户要求先把全部主体换基础几何，以 KB 小宣告优秀 |
| 有占位工厂与实例化消费者 | 核对具体返回类型、坐标和资源所有权，真实场景显示预期资产 | 工厂返回 Group 而消费者当 Mesh，兜底几何掩盖接口丢失 |
| 验收曾用调试传送/资源补给 | 局部夹具单列，另从干净开局正常输入走完 | 直接调用合并/胜利后把 G2 标通过 |
| 浏览器隐藏或失焦 | 查可见性、焦点、帧进度和输入后再诊断，恢复环境再操作 | 只看定时器/DOM 就断言卡死、凭空修游戏 |
| 开发监听仍开着时生产打包 | `.preview/` 与 `dist/` 分离，生产文件和报告 SHA-256 对应 | 开发重建覆盖生产 HTML，报告和发给用户的文件不一致 |
| 用户中途要求“直接打包” | 给当前包与层级，列失败/未验证项，不强制新审批 | 阻拦打包，或补写正常通关和离线已通过 |
| 禁止运行、只允许文件修改 | 完成源码/规格与静态检查，运行门槛保持未验证 | 偷跑构建/浏览器，或因为不能运行而只给空计划 |

## 模板工具的后续运行检查

以下是待执行的检查，不是本轮静态检查的结果：

- 在新目录生成骨架，确认质量契约与产物核对脚本均被复制；既有目录仍被拒绝覆盖。
- 生产构建后运行 `npm run verify:artifact`，应输出原始/gzip 字节和 SHA-256，并声明不评价玩法/视觉/离线。
- 开发服务器启动/重建只改变 `.preview/`；保持源码不变时核对 `dist/` 哈希不变。
- 在隔离副本分别修改 HTML、report 的模式/目录/字节/哈希，核对命令均应失败；不在用户交付文件上制造破坏。
- 用实际游戏按 `quality-contract.md` 跑 G1/G2/G3。只有骨架构建通过时，这一项仍为未验证。

## 比较优化前后

选取不同类型任务，保留优化前/后的同条件产物；固定参考、目标层级、平台、资产、运行授权与预算。分别记录视觉/手感/正常路线/交付的通过、失败与未知，评阅时隐藏生成来源以减少自证偏差。模型对比与 Skill 对比一次只改变一个主要变量；没有对照实验时只报告已知问题与改动，不声称提升了某个百分比。
